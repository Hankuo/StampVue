## 1. 產品定位與核心價值 (Product Overview)

### 1.1 背景與問題痛點
在行政、會計、合約與法務流程中，使用者經常需要將實體蓋章文件（如印鑑章、發票章、公司大小章、簽核印章）轉為數位印章圖檔。然而，現有手持拍攝或掃描常遭遇下列問題：
1. **紙張陰影與手機陰影**：手持拍照時手機鏡頭投射在紙上的暗影、紙張摺痕與不同光照產生的灰暗區塊，傳統單純以亮度或色差去背的工具常將陰影誤判為圖案保留，或將印章細節侵蝕。
2. **雜訊干擾與非印章內容**：拍到印章周圍的表格邊框、簽名文字、紙張邊緣髒污等。
3. **隱私與機敏外洩風險**：合約與印鑑屬高度敏感個資，若將印章原圖上傳至未知第三方公有雲 API 去背，具資安風險。
4. **即時互動反饋延遲**：上傳伺服器往返需 1~3 秒，微調滑桿體驗卡頓。

### 1.2 產品解決方案
**StampVue** 是一套專為印章數位化設計的專業影像處理工具：
- **雙引擎架構**：
  - **純前端 Client Canvas 引擎**：100% 於瀏覽器本機記憶體處理（5~20ms 超低延遲），即時拖曳滑桿即時反應，零個資上傳外洩風險。
  - **後端 Node.js / Sharp 引擎**：提供標準 REST API，支援大量非同步批次處理、自動定位與高畫質 PNG 轉存。
- **演算法核心**：
  - 雙通道自適應色彩對立色度差公式 (Color-Opponent Chromaticity Differential)。
  - Gamma 亮度感知非線性陰影抑制函數 (Luminance Gamma Shadow Suppression)。
  - 雙階濾除機制 (Two-Pass Coarse-to-Fine Pipeline)。
  - 粗階定位外側水淹演算法 (Enclosure Contour & Exterior Flood-Fill Eraser)。

| 角色 | 使用場景 | 核心痛點 | 期望產出 |
|---|---|---|---|

## 3. 核心功能與需求規格 (Features & Requirements)

### 3.1 影像輸入
- **鏡頭拍照**：調用裝置網路攝影機 (Webcam / 手機相機)，支援前/後置鏡頭切換。
- **本地上傳**：支援拖放 (Drag & Drop) 或點擊選取 JPEG、PNG、WebP，單檔上限 20MB。
- **剪貼簿貼上**：支援 `Ctrl + V` 直接將截圖貼入處理。

### 3.2 影像前處理與旋轉校正
- 提供 0° ~ 360° 旋轉滑桿與 90° 快捷旋轉，解決拍照方向歪斜問題。
- 自動校正 EXIF Orientation 資訊。

### 3.3 去背與色彩微調參數
- **印章色彩模式 (Color Mode)**：
  - `Auto`：演算法自動採樣計算主導色 (紅印 / 藍印)。
  - `Red`：紅色印章模式（針對朱肉、印泥、紅墨印章）。
  - `Blue`：藍色印章模式（針對藍色原子章、發票章、戳記）。
- **印章靈敏度 / 門檻 (Threshold: 10 ~ 100)**：決定印痕深淺辨識門檻。
- **陰影抑制程度 (Shadow Suppression: 0 ~ 100)**：增強暗部 Gamma 權重，強力剔除手機暗角與紙張陰影。
- **邊緣羽化平滑 (Smoothness: 0 ~ 50)**：使用 Hermite 曲線提供柔和反鋸齒透明漸變。
- **色彩飽和強化 (Color Boost: 0 ~ 100)**：補償老舊印章缺墨或氧化褪色，提升紅/藍飽和度。
- **自動主體裁切 (Auto Crop & Padding: 0 ~ 64px)**：自動分析主印章 BoundingBox，裁掉四周空白並加上自訂邊距。

### 3.4 預覽與對比
- **原圖與去背並排/疊加切換**。
- **多種檢視背景**：透明棋盤格 (Checkerboard)、白色紙張底、深色對比底。
- **雙向同步縮放與平移 (Pan & Zoom)**。

### 3.5 匯出與下載
- **一鍵下載 PNG**：匯出 32-bit RGBA 無損壓縮透明 PNG。
- **複製到剪貼簿**：直接將 PNG 二進位寫入系統剪貼簿。
- **REST API**：提供 `/api/stamp/extract`（支援 Base64 與 Binary Stream）。

## 4. 驗收標準 (Acceptance Criteria - AC)

### AC-1: 色彩對立與陰影剔除
- **Given**: 一張在昏暗光線下拍攝、具有明顯手機陰影（RGB 約 60~100 灰色）的紅印圖片。
- **When**: 系統以預設參數 (Threshold: 40, Shadow Suppression: 40) 處理。
- **Then**: 輸出影像中陰影區域的 Alpha 必須為 0（完全透明），紅印文字區域 Alpha 大於 200，印章字體無殘留黑邊。

### AC-2: 藍色印章與自動辨別
- **Given**: 一張藍色發票章圖檔。
- **When**: 使用者設定 Color Mode 為 `Auto`。
- **Then**: 系統自動辨識 `detectedColor: "blue"`，保留藍色印泥特徵，其餘黑白字跡完全去除。

### AC-3: 主體定位與外圍干擾隔離 (Flood-Fill Eraser)
- **Given**: 圖片中印章主體周邊 50px 外有紅色簽名或表格紅線。
- **When**: 啟用自動定位與主體裁切。
- **Then**: 系統成功以閉合輪廓與外側水淹演算法排除外圍連通元件，BoundingBox 僅鎖定印章本體。

### AC-4: 效能與即時性
- **Given**: 解析度 1920x1080 (約 200 萬畫素) 的拍攝圖片。
- **When**: 使用者在前端連續拖曳門檻滑桿。
- **Then**: 前端 Canvas 計算單次幀時間 < 30ms，無明顯 UI 掉幀或卡死。

### AC-5: 邊界背景與集中區域聚焦 (Border Background Elimination)
- **Given**: 拍攝照片邊界區域包含非印章之桌面、紙張邊緣或外圍雜訊（邊緣色偏）。
- **When**: 系統執行印章定位與自動去背。
- **Then**: 系統自動排除接觸或貼近照片邊緣的非主體雜訊，自動聚焦於內部高密度印章集中區域，裁切輸出影像不含邊界背景干擾。

### AC-6: 影像來源差異化處理 (Differential Source Pipeline: Camera vs Upload)
- **Given**: 使用者開啟「即時視訊拍攝」，畫面出現相機取景器與紅色裁切框。
- **When**: 使用者將印章置於裁切框中央並按下「按下快門擷取」。
- **Then**: 系統**依據視訊取景器上的裁切框精確裁切視訊畫面**，將裁切後之印章相片直接送入影像去背處理；**不需再經過第一步演算法自動偵測印章裁切流程**，即時呈現裁切框範圍內的高品質去背成果。
- **Given**: 使用者透過「選擇照片檔案」上傳整頁文件、發票或掃描圖檔。
- **When**: 執行去背影像處理流程。
- **Then**: **執行第一步印章偵測與定位**，裁切原圖至印章聚焦區域後進行第二步精細去背，自動去除文件周遭大片無關空白與雜訊。
